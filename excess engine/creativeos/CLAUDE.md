# CreativeOS Engine Constitution v2.0

> Supersedes v1.0, preserved as `CONSTITUTION-v1.0-superseded.md`. v1.0 is not
> discarded: under v2.0 its twelve engines are mostly **domain** engines, and
> they map onto StoryAtlas (Story/World/Character/Canon/Timeline) and the other
> applications rather than onto CreativeOS itself.

## Role

You are no longer building applications.
You are designing the **CreativeOS Engine**.

CreativeOS is the intelligence platform beneath an ecosystem of professional
creative software.

CreativeOS itself is not the storytelling application.
It is not the production application.
It is not the rights application.
It is not the portfolio application.

It is the operating system that gives every application intelligence, memory,
reasoning, connectivity and scale.

Every architectural decision should strengthen the operating system.

## Core Philosophy

Think like:
- Windows
- Linux
- AWS
- Adobe Platform
- JetBrains Platform

Not like:
- Notion
- Trello
- Canva
- Google Docs

CreativeOS exists so that entirely new creative applications can be built
rapidly without rebuilding the foundations every time.

CreativeOS owns universal intelligence.

**Never mix them.**

## Core Principle

CreativeOS should understand **knowledge**.
Applications should understand **domains**.

For example:

| Application understands | CreativeOS understands |
|---|---|
| StoryAtlas understands kingdoms | CreativeOS understands entities |
| RightsForge understands licenses | CreativeOS understands ownership |
| FilmCrew understands schedules | CreativeOS understands dependencies |

Applications provide meaning.
CreativeOS provides intelligence.

## CreativeOS Core Engines

These engines belong **ONLY** to CreativeOS.

### Knowledge Engine
Transforms every object into structured knowledge. Everything becomes an
entity: ideas, projects, assets, characters, locations, organizations, rights,
scenes, events. Nothing remains an isolated file.

### Identity Engine
Every entity receives a persistent identity. Identity survives renames.
Identity survives movement. Identity survives applications. Everything has one
identity.

### Graph Engine
Maintains the Creative Knowledge Graph. Every relationship exists here:
ownership, dependencies, references, membership, influence, inheritance,
timeline links. Applications contribute to the graph. CreativeOS maintains it.

### Memory Engine
Nothing is forgotten. Tracks version history, evolution, branches, creative
decisions, relationship history, knowledge history. Everything has memory.

### Context Engine
Builds contextual understanding. Assembles relevant information across every
application. Injects only necessary knowledge into AI reasoning. Acts as the
ecosystem's context layer.

### Reasoning Engine
Performs structured reasoning. Finds implications. Discovers relationships.
Predicts consequences. Builds recommendations. Never acts as simple retrieval.

### Verification Engine
Measures confidence. Detects contradictions. Tracks evidence. Validates
relationships. Surfaces uncertainty. Truth should never be assumed.

### Intelligence Engine
Coordinates every engine. Produces ecosystem intelligence. Answers: What
exists? What changed? What is connected? What matters? What is missing? What
happens next? This is the brain of CreativeOS.

### Search Engine
Hybrid search: semantic, keyword, knowledge graph, relationship search,
contextual search. Everything searchable.

### Event Engine
Everything emits events. Applications communicate **only** through events. No
tight coupling. CreativeOS becomes reactive.

### Workflow Engine
Coordinates automation. Triggers, pipelines, background tasks,
cross-application workflows.

### AI Orchestrator
Routes intelligence. Chooses models. Builds prompts. Injects context.
Coordinates AI providers. **AI is infrastructure, not product.**

### Storage Engine
Files, media, metadata, versions, snapshots, persistence.

### Platform Engine
Authentication, organizations, permissions, realtime, notifications, billing,
marketplace, plugin infrastructure, developer SDK. Everything shared.

## Architectural Rules

Every implementation must answer:

- Does this belong to CreativeOS or to an application?
- Is this universal knowledge or domain knowledge?
- Can another application reuse this capability?
- Does this strengthen the Creative Knowledge Graph?
- Does it preserve clear boundaries?
- Does it make the ecosystem more intelligent rather than simply adding
  features?

If a capability is universal, build it into CreativeOS.
If a capability belongs to one creative discipline, build it into the
corresponding application.

CreativeOS is not the destination. CreativeOS is the foundation that allows
every application to become exponentially more capable over time.
