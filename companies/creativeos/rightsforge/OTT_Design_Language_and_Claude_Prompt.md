# OTT Design Language

## Core Principle

**Software that respects thinking.**

Every OTT application should feel like it belongs to one ecosystem while
maintaining its own identity.

## Emotional Identity

Users should feel:

-   Calm
-   Focused
-   Intelligent
-   Premium
-   Cinematic
-   Intentional

Never playful for the sake of being playful. Never cluttered. Never
"corporate dashboard".

## Brand System

One shared design language across all products.

Shared elements: - Typography - Layout rhythm - Navigation - Motion -
Icons - Spacing - Interaction patterns

Each product gets exactly one signature accent color.

Example:

-   CreativeOS --- Blue
-   ContextCore --- Emerald
-   Veridact --- Violet
-   CanonChain --- Amber
-   StoryCore --- Crimson

The rest of the interface remains neutral: - Graphite - Black -
Off-white - Warm gray

## Typography

Typography should become recognizable.

Avoid excessive ALL CAPS.

Prefer: - Sentence case - Short headings - Clean hierarchy - Editorial
spacing

The feeling should be closer to a premium magazine or film title
sequence than enterprise software.

Create a custom OTT type system over time (and eventually a custom
font).

## Motion

Motion explains relationships.

Animations should: - reveal hierarchy - show connections - preserve
context

Never animate only for decoration.

## Connected Knowledge

Every OTT product should visualize relationships.

Information is not stored in isolated pages.

Everything connects: - people - documents - timelines - assets -
stories - decisions

Relationship views become part of the brand.

## Design References

Capture inspiration from products that create a strong emotional
response through interaction quality:

-   TikTok (fluid interaction)
-   Instagram (polished visual rhythm)
-   Linear (speed)
-   Notion (structured workspace)
-   Arc Browser (modern navigation)
-   Apple Human Interface principles (clarity)

Study *how they make users feel*, not how they look.

## OTT Signature

Every product should feel like:

> "Powerful enough for professionals. Calm enough to disappear behind
> the work."

## Master Prompt for Claude Code

You are the Design Director for the OTT ecosystem.

Design a unified design language shared across every OTT application.

Requirements:

-   One design system.
-   One interaction philosophy.
-   One typography system.
-   One motion language.
-   One icon family.
-   One spacing system.
-   One component library.

Each application must have: - one unique accent color, - its own subtle
personality, - while remaining unmistakably part of the OTT ecosystem.

Prioritize emotional consistency over visual novelty.

The interface should communicate intelligence, confidence, and focus.

Do not imitate existing products. Instead, study why products like
TikTok, Instagram, Notion, Linear, Arc, and Apple feel cohesive and
engaging, then synthesize an original design language.

The goal is that a user can instantly recognize any OTT application
without seeing the logo.


You are the founding Design Director of OTT. Your task is to create the complete OTT Design Constitution—a comprehensive design standard that every current and future OTT product must follow. This is not a component library. It is the philosophy, psychology, interaction model, visual language, typography system, motion language, accessibility standard, brand identity, knowledge visualization framework, AI behavior guide, and product architecture for an ecosystem of software. Study why Apple, Linear, Notion, Arc Browser, TikTok, Instagram, Figma, Stripe, and the world's best digital products feel cohesive. Do not copy their aesthetics. Extract the underlying principles that create trust, speed, delight, clarity, and emotional consistency. Then synthesize an original design language that is unmistakably OTT. Every future product—from CreativeOS to StoryCore, ContextCore, Veridact, CanonChain, and beyond—must inherit this system while retaining its own accent color and subtle personality. Produce this as a living constitution with chapters, rationale, examples, rules, anti-patterns, and implementation guidance. The document should be detailed enough that a new designer or engineer could build an OTT product that feels immediately recognizable without ever seeing another OTT application.
